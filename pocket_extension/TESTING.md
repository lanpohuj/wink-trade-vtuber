# Wink Trade 2.3.0 — проверка поиска и анализа

База механики сделки — a06c896 (2.2.3). Открытие одним кликом, четыре экспирации,
таймер 200 мс, результат, x2.2 и ключи статистики сохранены. Аватар и локальный
голосовой движок не менялись. Основные формулы ProTraderEngine сохранены;
сценарии теперь используют необходимые им интервалы.

## Что изменилось

- Видимые интервалы Pocket: M1 и S15. S30 выводится из S15, M2 — из M1;
  используются также распознанная история OHLC и тики с временем брокера.
- Матрица: 15s = S15/M1; 30s = S15/S30/M1; 1m = S30/M1; 2m = M1/M2.
  Контекст — закрытые свечи, вход — текущая свеча. Недостающий интервал
  отключает зависимый сценарий. EMA50 не считается готовой раньше 50 баров.
- Каждый источник помечен парой и периодом; запоздавшая история другого
  поколения не принимается. Анонимная история не приписывается текущей паре.
  Визуальный fallback сохраняет пиксельные единицы и приблизительные времена;
  агрегировать можно только соседние бары одного подтверждённого периода.
  Пиксельный ATR не применяется к реальной котировке микро-входа.
- Пары выбираются детерминированно по доходности, затем давности просмотра.
  До пяти успешно проверенных пар за круг, не более десяти попыток загрузки.
  Отсутствие данных после 3.2 с — пропуск, а не положительная оценка.
- Ранний вход: подтверждённый сетап и сумма факторов от 4.0/5. После круга:
  свежая проверка допустимых кандидатов по рейтингу от 3.5/5. Если лучший
  изменился — следующий кандидат; если все запрещены — новый круг.
  allowDominantEntry и десятисекундное наблюдение удалены.
- Анализ не чаще 250 мс. Четыре этапа показа — по 650 мс; готовый вход
  прерывает оставшийся показ. Карточка обновляется без пересоздания узлов;
  переход 200 мс выполняется только при смене пары/этапа.
- «Точность» = round(сумма проверенных факторов / 5 * 100). Подсказка:
  «Совпадение условий стратегии». Это техническая оценка, не измеренный винрейт.

## Автоматические проверки

```sh
node --check pocket_extension/content.js
node --check pocket_extension/page_hook.js
node --test pocket_extension/*.test.cjs
git diff a06c896 -- winky/web/avatar.js winky/app.py winky/server.py
```

66 тестов выполняют реальный код в моделируемых DOM/WS с управляемым временем.
Проверяются исходная механика сделки, x2.2, четыре экспирации, задержанная
выплата, REFUND/UNKNOWN и применение результата один раз; все тики пакета,
дробное время, бинарная история, поколение данных, точность малых цен;
реальное участие старшего интервала, недостаток истории и незакрытые бары;
ранний вход, рейтинг пяти пар, исчезновение сигнала при возврате, жёсткое
вето, свежесть котировки и отмена непосредственно перед кликом; стабильный
узел карточки и отсутствие роста «точности» от анимации.

Реальные формулы сценариев отдельно прогоняются на детерминированных
синтетических свечах для BUY/SELL. Тесты механики не доказывают доходность.
Серверная совместимость проверяется ASGI на изолированной БД в памяти.

## Диагностика и демо-проверка

Журнал последних 100 решений хранится только в памяти. В DevTools в контексте
content script Winky доступен `window.winkyDiagnostics()`: интервалы,
источники, баллы, запреты, отмены входа, локальный номер сделки и её результат.
Баланс, ключи и токены в журнал не добавляются.

1. При отсутствии открытой сделки обновить распакованное расширение до 2.3.0,
   полностью перезагрузить Pocket и убедиться, что выбран демосчёт.
2. Записать полный круг: M1 → S15, читаемые этапы без мигания, непустой селектор,
   номер пары и реальная оценка. Проверить ранний вход и выбор после пяти.
3. При жёстких запретах убедиться, что новый круг начинается без принудительного
   входа. При нехватке одного интервала проверить остальные сценарии.
4. Для каждого входа сверить пару, направление, сумму и длительность с Pocket,
   затем результат, W/L, чистый профит и голос Winky. Проверить
   LOSS→LOSS→WIN: $50→$110→$242→$50; третий LOSS также сбрасывает базу.
5. Проверить остановку авто-стрима во время загрузки и прямо перед входом.

Сверка результата остаётся прежней: до 10 с с шагом 300 мс, затем балансный
fallback наблюдавшейся сделки. Это отдельное окно расчёта, не наблюдение пары.
Выплата позже этого окна и сторонние ручные сделки остаются ограничением
балансного fallback версии 2.2.3. При отсутствии данных UNKNOWN не меняет
статистику/шаг и освобождает цикл.

Живая проверка и запись исправленного UI пока не выполнены: браузерный
инструмент возвращает `Local browser use is disabled in Work settings`.
Проверка DOM-модели, серверный HTTP 200 и деплой не заменяют демо-прогон
загруженного Chrome-расширения. Соответствие адаптера текущему DOM/WS Pocket
должно быть подтверждено после подключения браузера.
