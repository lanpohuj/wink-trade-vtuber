## 1. Что это за проект

Три связанные системы для продажи доступа к сигналам Pocket Option через TikTok Live:

1. **Telegram-бот (воронка)** — `bot/` на aiogram 3.x: выбор языка RU/EN, воронка
   «Регистрация → Депозит → Доступ», прогресс «Шаг N из 3», соцдоказательство
   (счётчики из БД), ежедневный тизер в 19:00, админ-команды. Бот: **@winktrade_bot**.
2. **FastAPI-бэкенд** — `api/` + `main.py`: Postback API от Pocket Partners,
   генерация сигналов, живая лента, геймификация, раздача Mini App.
3. **Telegram Mini App** — `webapp/` (Vanilla JS, без сборки): тёмный неоновый UI,
   сигналы с драматургией (свечной график → этапы анализа → reveal + звук +
   хаптика), таймер экспирации (нейтральное затухание — НЕ рисуем выдуманные
   исходы сделок!), живая лента, геймификация (баллы → недельный топ-10).
4. **Winky** — `winky/` VTuber-агент: работает ТОЛЬКО на Mac владельца (не в
   Docker!). 3D-модель Shibahu (three.js + FBX), голос macOS say → ElevenLabs
   по ключу, пульт-окно, скрытый режим стримера, TikTok-чат + DeepSeek-мозг.

**Оригинальное ТЗ** — `Spec.md`. **План/история этапов** — `ROADMAP.md`
(этапы 1–4 выполнены, включая деплой; внутри — рецепты постбека 4.5 и чек-лист лайва).

## 3. Интеграция Pocket Partners (не ломать!)

* Партнёрская ссылка формируется в `config.partner_url(tg_id, lang)`: базовая ссылка
  **не меняется**, в КОНЕЦ дописывается `sub_id1=<telegram_id>` (их правило:
  сокращатели/редиректы/правки базы рвут атрибуцию).
* Postback: `GET|POST /api/postback` с `token=<POSTBACK_SECRET>` (или заголовок
  `X-Postback-Token`). Параметры: `event=reg|dep` (алиасы registration/deposit),
  пользователь ищется по приоритету **`sub_id1` → `tg_id` → `sub_id` → `utm_source`**,
  `trader_id`, `amount`. В дашборде партнёрки настроены два постбека
  (Registration и First Deposit) — полный рецепт в ROADMAP 4.5.
* `dep` с любым amount (даже 0) ставит `has_access=True`; `reg` сохраняет `trader_id`.
* Все постбеки пишутся в `postback_logs` (raw без токена); 403/400 до журнала не доходят.
* В `.env` именно `RU_PARTNER_BASE_URL/EN_PARTNER_BASE_URL` — поля конфига названы
  так же. PARTNER_BASE_URL — только fallback.

## 4. Грабли, на которые уже наступали (не повторять!)

**Деплой/сервер:**
* `deploy.sh`: в rsync-exclude НИКОГДА не писать паттерн `_*.py` — он выкидывает
  все `__init__.py` (приложение не стартует). Только `_test*.py`/`_dev*.py`.
* Серверный образ собирается из `requirements-server.txt` (БЕЗ winky-пакетов:
  `evdev` от pynput не собирается в slim-контейнере). `requirements.txt` —
  полный, для мака.
* `main.py`: `logging.basicConfig` — на уровне модуля, НЕ в `__main__` (под
  uvicorn иначе docker logs пустые).
* Приложение устойчиво к невалидному `BOT_TOKEN` (API-only режим, лог
  «Telegram-бот отключён»); постбеки применяют БД даже без бота (пуш
  пропускается) — это осознанное поведение, не ломать.
* SQLite теряет timezone offset: при отдаче дат наружу всегда помечать UTC
  (`as_utc` в api/signals.py, `_as_aware` в crud.py) — иначе лента «420мин назад».

**Mini App (webapp/):**
* CSS: правило `[hidden]{display:none !important}` обязательно — иначе `display:flex`
  классов перебивает атрибут hidden (чек-лист анализа не скрывался).
* OTC-сигналы детерминированы по 5-секундным окнам (hash), классика — TradingView
  с фоллбэком на momentum-расчёт (таймаут 5с, кулдаун 60с, кэш 30с).
* Таймер экспирации заканчивается НЕЙТРАЛЬНЫМ затуханием: никаких «WIN» —
  исход сделки неизвестен, зрители поймают на лжи.
* Режим стримера: тап по логотипу → `force_dir: BUY`, по заголовку «Signal settings»
  → SELL; сервер применяет только для ADMIN_TG_IDS.
* Геймификация: дневной лимит 27 (сигналы + заход 5 + серия до 7), недельный
  ключ ISO `%G-W%V`, сброс в понедельник; правила в /api/me — без финансовых
  обещаний (требование партнёрки/TikTok).

**Winky (winky/ — только Mac):**
* **VRM 3D-движок (@pixiv/three-vrm)**: Модель аватара переведена на индустриальный стандарт VRM (`winky/web/model/avatar.vrm`).
  - `@pixiv/three-vrm` 3.5.5 + `GLTFLoader` подключены через ES Module Importmap (`avatar.html`).
  - Готовые физические пружинные кости `SpringBoneManager` для волос/лент (настоящая инерция вместо синусоид).
  - Настоящий Humanoid Rig с нормализованными костями (`getNormalizedBoneNode`).
  - Внимание: после манипуляций с костями гуманоида ОБЯЗАТЕЛЬНО вызывать `this.humanoid.update()`, иначе повороты нормализованных костей не переносятся на скелет меша!
  - Руки в покое: для опускания рук по швам нормализованный угол Z: `leftUpperArm.rotation.z = +1.25`, `rightUpperArm.rotation.z = -1.25` (отрицательный Z для левой руки поднимает её в потолок!).
  - Спектральный фонемный Lip-Sync: гласные `aa`, `ih`, `ou`, `ee`, `oh` через `vrm.expressionManager` с Web Audio частотным анализом + процедурным слоговым фоллбэком.
* **Озвучка Lumean (Strict Female Voice)**:
  - Исключительно женский голос ElevenLabs через Lumean API (template `01a17652-9182-70a1-8889-8245fbb437c0`, voice `iP95p4xoKVk53GoZ742B`).
  - Полный запрет отката (fallback) на роботизированный мужской голос macOS `say Yuri`! При сбоях или перегрузке очереди Lumean поднимается `TTSError`.
  - Таймаут опроса очереди Lumean увеличен до 120 с (у них пакетная асинхронная очередь `queue_position > 10`).
  - Пульт Winky (`panel.html` / `panel.js`) содержит поля для динамической смены Lumean Template ID и Voice ID с сохранением на лету.
* pywebview: `transparent=True` НЕ работает само — нужен нативный фикс
  `drawsBackground=NO` + clearColor (метод `apply_native_transparency` в
  winky/app.py, вызывается из avatar.js по pywebviewready).
* WebGL в прозрачном WKWebView композитится ЧЁРНЫМ → рендер дублируется в
  2D-canvas (`presentFrame()`), виден прямой GL-канвас, 2D-копия скрыта
  (только для скриншот-отчётов). Не удаляй её.
* FBX Shibahu НЕ содержит имён файлов текстур (`/model/undefined`!) — текстуры
  назначаются вручную по именам материалов (`diffuseByMaterial` в avatar.js:
  Body_mt→Shibahu_body_dif.png и т.д.). Палитра модели тёмная (оригинал на
  Sketchfab тоже силуэт) → попиксельный буст яркости при загрузке
  (`brightness *1.18 +30`); `ctx.filter` в WKWebKit НЕ работает — только
  getImageData/putImageData.
* Меши контура `*_line` (`body_line`, `hairA_line`, `jacket_line` и т.д.):
  НЕ рендерить с BackSide — они полностью перекрывают персонажа чёрным силуэтом
  (99.63% `#1a1518`). Ставить `child.visible = false` (линии уже нарисованы на
  диффузных текстурах). На `face_mesh` слот `lineA_mt` (9762 индекса) — это контурная
  оболочка лица: ОБЯЗАТЕЛЬНО `visible: false`, иначе лицо покрывается сплошной чёрной маской.
* Мимика и Lip-Sync:
  - Морфы автора модели объединяют движение век и рта (`face_mesh2` опускал веки на -2.22 мм, из-за чего аватар щурился при речи).
  - При загрузке FBX процедурно извлекаются изолированные морфы рта: `pure_mouth_jaw` ($Y < 137$ из морфа 14) и `pure_mouth_smile` ($Y < 137$ из морфа 0) с полным обнулением зоны глаз.
  - Речь управляется строго через `pure_mouth_jaw` + `pure_mouth_smile`: глаза остаются на 100% распахнутыми, живыми и сияющими.
  - Исключить морфы оскала (`face_mesh6`, `face_mesh4`) и хмурых бровей (`face_mesh3/3_2`).
  - Dual-Engine Lip-Sync: при речи обязательна процедурная слоговая артикуляция (4.8 слога/сек) + кивки головы, даже если Web Audio отдаёт 0.
  - Игривый стиль: периодический wink каждые 6-12 с в покое, ускоренный темп речи (1.15x).
* Анатомия ушек и хвоста:
  - Ушки: цепочка костей содержит дублированные ноды. Кость `Shibahu_Ear_Right1` имеет rest rotation `z = -2.84` рад (~163°). НИКОГДА не затирать `rotation.z = 0` по всей цепочке — это складывает ухо внутрь головы! Анимировать только корневые кости `Shibahu_Ear_Left1` и `Shibahu_Ear_Right1` относительно `initRot.z` с деликатной дельтой ($\pm 0.04$ рад).
  - Хвост: корень `Shibahu_Tail1` имеет rest rotation `[0.91, 1.57, 0]` (хвост назад за правое бедро). НИКОГДА не трогать `Tail1` — обнуление угла разворачивает хвост на 90° вперед сквозь живот и шорты! Анимировать только звенья `Tail2..Tail4` по оси Z относительно `initRot.z` с амплитудой $\le 0.04$ рад.
* Анимация `Take 001`: демо-петля автора модели на 11 секунд — НЕ запускать
  (`action.play()` отключён), иначе аватар выглядит как зацикленный GIF.
  Вместо неё работает процедурная жизнь VTuber: естественное дыхание,
  микродвижения головы, подёргивание ушек, автоморгание каждые 3-5 с и Lip-Sync.
* Румянец (`Cheek_mt`): использовать `Shibahu_cheek_msk.png` как `alphaMap` и
  динамическую прозрачность от морфа `facial_cheek` (`opacity = 0.85 * blush`).
* Кадрирование: базовый масштаб `1.25 / size.y`, камера на высоте 0.98 м и
  дистанции 1.70 м обеспечивает ~20% запаса воздуха над ушками. Регулировка
  размера (Zoom 50-150%) и высоты Y доступна стримеру прямо из пульта.
* Морфы модели: face_mesh2=рот (открытие челюсти), face_mesh8=рот 'О',
  face_mesh1/1_2=моргание L/R, face_mesh9/9_2=подмигивание L/R, facial_cheek=румянец,
  facial_irisHilight_Big=блеск глаз. ВНИМАНИЕ: face_mesh4 — это НЕ улыбка, а оскал зубов
  (2152 белых пикселей зубов!), face_mesh4_2 — прищур, face_mesh3/3_2 — хмурые брови,
  face_mesh6 — оскал. Все они ДОЛЖНЫ БЫТЬ ОТКЛЮЧЕНЫ. Натуральная милая улыбка уже есть
  на диффузной текстуре Shibahu_face_dif.png.
  (расшифровка контактным листом — window.winkyDebug).
* Проверки GUI: `WINKY_SMOKE=N` (автозакрытие окон) + `screencapture -x` +
  пиксельный анализ Pillow. Vision-модели НЕ доверять в вопросах цвета.
* SpeechController: очередь с цензурой на входе и выходе, `finish_current()`
  из JS обязателен; tts-файлы живут в winky/web/media (контекст pywebview).
* Глобальные хоткеи pynput требуют «Универсального доступа» macOS; поток
