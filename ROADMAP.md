# Wink Trade — Roadmap: «Продажа с лайва» + VTuber-агент Winky

Зафиксировано по итогам интервью (grill-me). Порядок: **Бот → Winky → чат/LLM → прод**.
Каждый этап — законченная рабочая сущность. Ничего не начинать из следующего этапа,
пока текущий не принят.

## Сцена лайва (общая картина)

- Стример держит **iPhone с Mini App** в кадре — живые сигналы на реальном телефоне.
- В области захвата OBS — **реальная вкладка Pocket Option**, где стример торгует.
- **Winky** — аниме-аватар с неоном — плавает **поверх** всего прозрачным
  always-on-top окном без фона (перетаскивается мышью).
- **Пульт управления** — отдельное окно, всегда ВНЕ зоны захвата OBS.
- Путь зрителя: ссылка `t.me/<bot>?start=live` в шапке TikTok-профиля + CTA от Winky
  каждые 3–5 минут. Бот запоминает источник — конверсия лайва видна в `/stats`.

## ЭТАП 1 — «Драма в боте» (Mini App + воронка)

Цель: зритель, увидевший бота на лайве, хочет его немедленно. Всё локально, тесты офлайн+браузер.

- [ ] 1.1 БД: таблица `signal_history` (pair, direction, accuracy, duration, tg_id,
      created_at) + crud: `save_signal`, `get_recent_signals`, счётчики
      (`today_signal_users`, `total_users`). Поля `users`: `source` (метка start-payload),
      `push_paused`, `teaser_count`, `last_teaser_at`. Лёгкая миграция в `init_db`
      (CREATE TABLE IF NOT EXISTS + ALTER TABLE ADD COLUMN с игнором «duplicate column»).
- [ ] 1.2 API: `/api/signal` пишет выданный сигнал в `signal_history`;
      новый `GET /api/history` → последние 6 сигналов + счётчики сегодня/всего одним ответом.
- [ ] 1.3 Mini App — драматургия:
      - «мышление» 2.5–3 с: этапы анализа с чекпоинтами
        (Загрузка данных → RSI → EMA → Подтверждение), прогресс-полоса, затем
        эффектный reveal (scale-in + glow + хаптика notificationOccurred).
      - звук: короткий синтезированный «дзынь» при reveal (WebAudio, без файлов).
      - лента истории: последние сигналы платформы («N сек назад», пара, направление,
        точность) + строка «🔥 Сегодня сигналы получили N трейдеров».
      - таймер экспирации после сигнала: тикающее кольцо/полоса; по нулю —
        **нейтральное затухание** (без выдуманного исхода), отметка «отработан» в ленте.
- [ ] 1.4 Воронка бота:
      - прогресс «Шаг 1 из 3: Регистрация → Депозит → Доступ» во всех статусных
        сообщениях (локали RU/EN).
      - счётчики в welcome: «🔥 Сегодня N» всегда + «👥 Всего M» при M ≥ порога из конфига.
      - `/start <payload>`: метка источника (`live`, `organic`) в `users.source`.
      - `/stats` расширен: разбивка по источникам + счётчики сегодня/всего.
- [ ] 1.5 Ежедневный тизер: asyncio-планировщик в main.py, 19:00, 1 раз/день, только
      юзерам без доступа, максимум 7 раз подряд, кнопка «⏸ Не присылать»
      (callback → `push_paused=True` навсегда). Локали RU/EN.
- [ ] 1.6 Проверка: офлайн-тесты (feed_update + httpx) + браузерный прогон Mini App.

## ЭТАП 2 — Winky v1 (локально, без TikTok)

Цель: анимированная Winky с голосом и пультом, работающая на маке поверх любых окон.

- [ ] 2.1 Каркас `winky/`: pywebview, ДВА окна — аватар (прозрачный, always-on-top,
      frameless, перетаскивание мышью за тело) и пульт (обычное окно).
- [ ] 2.2 Аватар: SVG-персонаж (аниме + неон: зелёные пряди, наушники, лого Wink Trade).
      Состояния: idle (моргание, дыхание-покачивание), talking (рот по амплитуде речи),
      эмоции: happy / excited / thinking / wink. CSS-переходы.
- [ ] 2.3 TTS: интерфейс движка — старт на macOS `say` (ru/en голоса), переключение на
      ElevenLabs по ключу в .env (один multilingual голос). Очередь фраз,
      амплитуда для lipsync через Web Audio Analyser.
- [ ] 2.4 Пульт: кнопки быстрых реплик и эмоций, поле «сказать вслух» (с выбором языка),
      громкость/пауза, глобальные хоткеи (пауза, повтор CTA).
- [ ] 2.5 Сценарии: `winky/scenarios.yaml` — что/когда/на каком языке говорить
      (триггеры: ручные кнопки, приветствие, CTA каждые N минут), плейсхолдеры {user}.
      Автоперезагрузка файла при изменении.
- [ ] 2.6 Цензура-модуль (общий для этапа 3): стоп-слова
      (гарант*, 100%, без риска, …) + хук чёрного списка тем из конфига.
- [ ] 2.7 Ручная проверка: прозрачность поверх браузера, drag, голос, эмоции.

### 4.5 Рецепт настройки постбека в дашборде Pocket Partners

Наш эндпоинт: `https://<домен>/api/postback` (секрет — параметром `token=<POSTBACK_SECRET>`
или заголовком `X-Postback-Token`). В дашборде создать два постбека (макросы слева —
имена наших параметров справа):

| Событие партнёрки | URL-параметры |
|---|---|
| Registration | `event=reg&token=СЕКРЕТ&sub_id={sub_id1}&trader_id={trader_id}` |
| First Deposit | `event=dep&token=СЕКРЕТ&sub_id={sub_id1}&trader_id={trader_id}&amount={sumdep}` |

* `{sub_id1}` — в него попадает tg_id пользователя (наша ссылка добавляет
  `sub_id1=<tg_id>` в конец партнёрской ссылки — по их правилу «дописывать только в конец»).
* Правила академии: не менять базовую ссылку, не использовать сокращатели,
  Local postback кампании перекрывает глобальный.
* Опционально добавить Re-deposit → тот же `event=dep` (суммы сложатся),
  Commission/Withdrawal — наш эндпоинт примет как неизвестное событие (400) —
  по решению владельца статистика комиссий смотрится в дашборде партнёрки.

## Принципы

- Никаких выдуманных исходов сделок и фейковой статистики: только реальные данные из БД.
- Цензура реплик — всегда на выходе, до озвучки.
- Каждый этап завершаем проверкой (тесты/браузер/ручной прогон) до перехода к следующему.
